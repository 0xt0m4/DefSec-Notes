
**Endpoint Detection and Response** is a security solution to monitor, detect and respond to advanced threats at the endpoint level. (meaning it won't detect network-level threats)


==Endpoints== are basically the devices, that are connecting to the network. 
Endpoint protection has been critically important to defend, as they are exposed via remote work.


Some EDR solutions:

- CrowdStrike Falcon
- SentinelOne ActiveEDR
- Microsoft Defender for Endpoint
- OpenEDR
- Symantec EDR

# EDR Over AV

A popular question, which can might come up in an interview is, 

_Why do we need EDR when we already have Antivirus on the endpoints?_


Quick answer is, EDR is more strict, and has more features == safer for environments

## Example

We're at the airport. The immigration (AV) checks whether the entered card belongs to a criminal. 
If yes, the entry is blocked and starts yelling

But what if you're an innocent person? The entry is wide open. However, that "innocent person" can simply be a professional thief, who trained to evade the security check.


The antivirus would leave at after the check, while the EDR would watch him through the wole time on CCTV

The EDR would monitor events as:
- Are they roaming close to restricted areas?
- Is their behaviour suspicious?
- Are they leaving bags somewhere unattended?


## Tehcnical Example

1. Let's say the user clicked on an email, which downloaded an SVG file, that ran a macro
	**AV** does nothing if the file as no signature in the database
	**EDR** Logs and monitors it

2. Which then executed, and spawned a powershell
	**AV** Does nothing scimce winword.exe is a legitimate utility
	**EDR** Records the execution and keeps monitoring

3. The command downloaded a second-stage payload
	**AV** does nothing since the macro has no known signature
	**EDR** detects the unusual parent-child relationship of winword.exe and the powershell process

4. The payload is injected to a legitimate svchost.exe
	**AV** Lacks network level visibilty
	**EDR** Flags unexpected behavior of svchost.exe making an outbound connection

5. The attacker has compromised the system
	**AV** may be marked everything as clean...
	**EDR** generates an alert of the attack chain and enables the analyst to take actions from within the EDR!

# EDR Telemetry


Telemetry is basically the data, form what the agents collect their endpoints and push ti the EDR console. (The summarized output)

Which are basically:

- **Process Execution and Terminations**: 
	It keeps the running and idle processes, that helps you identify suspicious child-parent process relationships, executables initiating a process, malware payload etc.
- **Network Connections**:
	The network connections of the endpoints, that helps you identify connections to a C2(_sophisticated reverse shell_) server, unusual port usage, data exfiltration or lateral movement
- **Command Line Activity**:
	Command executed on the endpoints, that helps you identify malicious command executions
- **Files and Folders Modifications**:
	Monitors different file and folder modifications during data staging, ransomware executions and malicious file dropping
- **Registry Modifications**:
	There are many malicious activity that involves registry modifications, and most of them are monitored by the EDR


# Detection and Response Capabilites


![[Pasted image 20251116201326.png]]


Based on the **telemetry** recieved from the endpoints, some detection and response techniques are applied to this data.

Which are

1. **Detection:**

- Behavioral Detection:
	Instead of simple signature checks (unlike an antivirus) the telemetry observes the complete behavior of a file. 
	E.g `winword.exe` spawns `powershell.exe` will be flagged do to it's behavior, cause it's an _unusual_ parent-child behavior
- Anomaly Detecion:
	Any unusual behavior (or anomaly) will be flagged.
	E.g on an endpoint, a process modifies an auto-start registry key, which isn't a common behavior for and endpoint.
- IOC matching
	Except 0-days, every attacks have indicators published in threat intelligence feeds. EDR flags these activities that matches any `IOC` 
	E.g A downloaded file is an executable. If the hash of this file matches any IOC, it will be instantly flagged!
- MITRE ATT&CK Mapping
	Any activity marked malicious will be also mapped with the MITRE attack stage 
	E.g the EDR flags the creaton of a scheduled task for any reason, it will map this activity to the following: `Tactic: persistence` or `Technique: Scheduled Task/Job`
- Machine Learning Algorithms
	Modern EDRs are trained with ML algorithms to detect bypass techniques, and complex attack chains
	E.g an action is not malicious itself, but the machine learning has seen it in a complex chained attack. Fileless attacks and multi-staged intrusions are often detected with this! 


2. **Response:**

- Isolate Host
	Easily isolate the host from a network, in case of malicious activity. This can prevent lateral movements to other endpoints.
- Terminate Process
	In cases where the termination of a process can be enough, or can't isolate the host through its "buisness activities" it runs, can be a simple solution
- Quarantine
	Malicious files can be quarantined, which ensures that the file is moved to a location where it can't be executed. So later the analyst can review it
- Remote Access
	Easily get a shell if built-in response is not enough to take action
- Artefacts Collection
	You may need to extract some date for investigation. The most commonly extracted artefacts are: memory dumps, event logs, specific folder contents and registry hives

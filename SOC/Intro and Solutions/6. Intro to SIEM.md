**Security Information and Event Management System** is a security solution to collect, normalize and correlate logs.


Logs are coming from any kind of devices, including Linux and Windows machines, data servers and web-servers. These can be events like 
- A user attempting to authenticate
- A process modification
- A file being access via FTP
- SSH connection
and many more!

These can be broken down into 2 categories:
_Host-centric_ logs and _network-centric_ logs



# Why SIEM

SIEM is the solution to get these logs standardized, get their sources, their format into a consistent one, to easily correlate them, and detect malicious activities using detection rules


# Features


- **Centralized Log Collection**
	SIEM collects logs from ALL sources and centralizes them into one place. 
- **Normalization of Logs**
	SIEM makes logs look in a consistent format, and parses the output in a way that's easy to read
- **Correlation of Logs**
	Individual logs are not always useful, so SIEM correlates the logs of different sources, and finds the relationships between them (a log-in from a different IP, then document access, then CMD execution them an outbound connection)
- **Real-time Alerting**
	SIEM comes with default rules, but everyone can make their own, based on their requirements.
- **Dashboards and Reporting**
	The dashboard presents the parsed logs and data, which are custom solutions, so most dashboards are different somehow


# How it Actually Works


Detection rules are basically logical expressions set to trigger events. 
For example:

- If a user gets five failed login attempts in 10 seconds, raise an alert for `Multiple Failed Login Attempts`
- If a successful login made after failed attempts, raise an alert for `Successful Login After multiple Login Attempts`
- When a user plugs in a USB its alerted, and everything gets monitored, then reported
- If outbound traffic is more than _25 MB_, raise an alert for `Potential Data Exfiltration Attempt`

## How is a Detection Rule Created?


1. Use case:
	During post-exploitation, the attacker tends to remove their tracks. A unique Event ID **104** is logged when a user tries to clear the logs
	IF():
		Log source == WInEventLog && EventID == 104;
		alert('`Event Log Cleared!`');


2. Use case:
	adversaries use commands like `whoami` after exploitation/privilege escalation. 
	- Log source capturing events
	- Which Event ID is related to Process Execution activity? In this case, Event ID 4688 will be helpful
	IF():
		Log source == WinEventLog && EventCode == 4688;
		alert('`WHOAMI command Execution DETECTED`')

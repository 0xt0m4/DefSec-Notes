- **Alert Reporting:**

	Before passing the alert to L2, you might have to report it, depending on **team standards**. 
	Sometimes, a comment is enough, whereas other companies require to write some sort of document, to ensure the evidence. 



- **Alert Escalation:**

	If True Positive requires action or deeper investigation, you'll escalate it to te L2 for further review
	That's where the report can become handy, so he don't have to regain the base information, and can start to investigate!



- **Communication:**

	You might need to communicate with other `department`
	For example, ask the HR to get more information about the recently hired employee



# Reporting Guide 


**Why** should you write reports:

| **Alert Report Purpose**       | **Explanation**                                                                                                                                                   |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provide context for escalation | - A well-written report saves lots of time for L2 analysts<br>- Also, it helps them quickly understand what happened                                              |
| Save findings for the records  | - Raw SIEM logs are stored for 3-12 months, but alerts are kept indefinitely<br>- As a result, it's better to keep all the context inside the alert, just in case |
| Improve investigation skills   | - If you can't explain it simply, you don't understand it well enough<br>- Report writing is a great way to boost L1 skills by summarising alerts                 |


# Report Requirements:

---
Report **format:**

- **Who:** which user logs in, runs the command, or downloads the file
- **What:** What action/sequence was performed
- **When:** When exactly did the activity start and ended
- **Where:** Which device, IP or website was involved
- **Why:** The most important: the ==reasoning== for your final verdict

---


Example:
```report
The IT Manager (Eddie Huffman, <e.huffman@tryhackme.thm>) opened the suspicious file. The description of the email was about a "600% price increase of an urgent notice, about to download the report, and read it's details". 
The email was opened at Mar 27th 2025 at 19:25.
The sent file was a rar file named "REPORT.rar"

The sender claims to be the Microsoft Support <support@microsoft.com>, but the file is in a rar format, which failed both by the SPF and DKIM. 
Immediate investigation required!
```

# Escalation

Escalation **Reasons:**

After the verdict and report, you must chose whether to escalate the alert to L2. 
These kind of alerts are:

1. The alert is an indicator of a major cyberattack requiring deeper investigation or DFIR
2. Remediation actions like malware removal, host isolation, or password reset are required
3. Communication with customers, partners, management, or law enforcement agencies is required
4. You just do not fully understand the alert and need some help from more senior analysts


Escalation **Process:**

You have to **reassign the alert to the L2 on shift**, and ping them (write a message or talk to them). Tough you may be required to create a 
**formal written escalation request** with dozens of required fields.
